# Як читаються файли {#how-the-files-are-read}

| Частина | Статус |
|---|---|
| Архіви (`data/*.gtp`, Great Battles) | таблиця файлів (записи `S16R`, `STRMFAT?`, `DIR!`/`FILE`) і записи (заголовок `STRMFILE`, дані зберігаються як є); кожен `Maps*.gtp` тестової інсталяції |
| `height.hini` | `height_map`, `water_map`, `heightMul`, `SeaLevel`, межі ігрової зони і `MapNW/NE/SE/SW`; кожен файл тестової інсталяції |
| Карти висот (`height.dat`) | кодек нижче; кожен сектор карт, декодований повністю під час роботи над ним, використовує свій бітовий потік точно (максимум залишок байтового доповнення), решта перевірена за заголовком. Перевірено побітово з нестисненими файлами `distlod.raw`, які гра поставляє поруч зі своїми `distlod.dat`, і з власною картою висот далекого рівня деталізації карти (кореляція 0,999) |
| Висоти | метри = сире x heightMul / 256 - SeaLevel x heightMul. Море карти декодується в точно ту висоту, яку вказують коментарі її hini; межа іншої — у її `bounds_level` |
| Розміщення | білінійне між чотирма кутами hini, рядок 0 — північ, стовпець 0 — захід. Перевірено на карті за відомими містами, узбережжями і морями (висоти міст у межах близько 10 м від справжніх, моря нижче рівня моря). Кути — це чотирикутник, а не власна проєкція гри, тож на середині великої карти очікуйте похибку в кілька сотень метрів. Hini однієї родини карт містить кути іншої карти (вони охоплюють частину її справжнього розміру); це виявляється, і ця родина розміщується натомість підгонкою за орієнтирами: міста й аеродроми з баз даних місцезнаходжень гри (`*.ldfbin`) порівнюються з їхніми справжніми позиціями, середньоквадратична похибка кілька кілометрів (міста — з аеродромами, названими на їхню честь, а координати справжніх місць — з точністю до близько кілометра); JSON перелічує кожен орієнтир і його похибку |
| Маска води (`water.wtr`: чотири рівні піраміди тайлів, кожен тайл — таблиця блоків по 400 м, кожен блок — суша, повністю або частково вода з формою в бітовому потоці) | контейнер читається на кожній карті (жодного залишку байта у файлах, декодованих повністю); форма всередині блоку, частково зайнятого водою, **не декодується**. Повністю заповнені блоки — це вода; у частково водних блоках відлік — вода там, де карта води (`height_w.dat`, той самий кодек, що й у карти висот) вища за землю, або, поруч з озером, там, де земля не вища за озеро; блоки суші сухі. Це прибирає болото, яке сама карта води позначає як воду. Річки, вужчі за вихідну сітку, виходять розірваними на шматки |
| Контури міст (сітки декалів, які перелічує `textures.tini`: `towns.mesh`, `cities.mesh`, `city_*.mesh`, `roads_fields.mesh`, ...: тайли по 25,6 км плоских текстурованих трикутників) | читаються на кожній карті; грані, чия текстура — місто, село або промислова земля, зберігаються. Перевірено з реальними містами на кількох картах (місто на обох берегах річки, злиття). Це контури: гра розміщує будівлі під час роботи, а файли будівель не містять |
| Аеродроми, мости, будівлі | **не читаються**: аеродроми — це об'єкти місій, будівлі походять із власного розміщення гри |
| Ліси (`forest_map.wtr`) | його блоки читаються так само, але майже кожен блок — це «частково ліс», тож без бітового потоку немає придатної маски лісу; не малюється |
| Текстури землі | не читаються |

## Кодек карти висот {#the-heightmap-codec}

Виведено лише з файлів даних; жодного коду гри не читалося і не розбиралося.
Порядок байтів — little-endian:

```text
u32 width, u32 height, u32 sectorsX, u32 sectorsY, u32 sectorSize, f32 cellSize
u32 offset[sectorsX * sectorsY]            від початку файлу, по рядках, верхній рядок першим
sector: u16 count (байти, що йдуть далі), u16 mode ((log2 sectorSize) << 4 | LW, LW = 4),
        потім бітовий потік, що читається від старшого біта:
  PRE   2 * (log2(sectorSize) - 5) біт, досі завжди 0
  LIT   перший відлік: знак (1), n (LW біт), величина (n + 1 біт)
  потім, доки сектор не заповниться:
    0 LIT       наступний = попередній + LIT
    1 RUN LIT   попередній відлік повторюється RUN разів (k: 3 біти, m: k + 1 біт, RUN = m + 1),
                потім (якщо сектор не заповнений) наступний = попередній + LIT
  значення — 16-бітні: читаються за модулем 65536
```

Неповні сектори на правому і нижньому краях доповнюються і обрізаються. Той самий
кодек використовується для карти води і карти висот далекого рівня деталізації.

## Підгонки за орієнтирами {#landmark-fits}

Там, де кути карти не можна використати, `landmarks.py` підганяє афінне відображення
метрів гри на Землю методом найменших квадратів: позиції в грі — з власних файлів
користувача (блоки `Airfield` місій, бази даних місцезнаходжень кар'єри), справжні
позиції — з таблиць опублікованих координат місць у коді. У `georeference` JSON містяться
матриця, початок, кожен орієнтир з його похибкою і середньоквадратична похибка.
