# Как читаются файлы {#how-the-files-are-read}

| Часть | Статус |
|---|---|
| Архивы (`data/*.gtp`, Great Battles) | таблица файлов (записи `S16R`, `STRMFAT?`, `DIR!`/`FILE`) и элементы (заголовок `STRMFILE`, данные хранятся как есть); каждый `Maps*.gtp` проверочной установки |
| `height.hini` | `height_map`, `water_map`, `heightMul`, `SeaLevel`, пределы игровой зоны и `MapNW/NE/SE/SW`; каждый файл проверочной установки |
| Карты высот (`height.dat`) | кодек ниже; каждый сектор карт декодирован полностью во время работы над ним, и его поток битов используется точно (не больше остатка байтов до выравнивания); остальное проверено по заголовку. Проверено побитово по несжатым файлам `distlod.raw`, которые игра поставляет рядом со своими `distlod.dat`, и по собственной карте высот дальней детализации карты (корреляция 0,999) |
| Высоты | метры = сырое × heightMul / 256 − SeaLevel × heightMul. Море карты декодируется в точно ту высоту, которую указывают комментарии её hini; граница другой — в её `bounds_level` |
| Размещение | билинейно между четырьмя углами hini; строка 0 — север, столбец 0 — запад. Проверено на карте по известным городам, побережьям и морям (высоты городов в пределах около 10 м от настоящих, моря ниже уровня моря). Углы образуют четырёхугольник, а не собственную проекцию игры, поэтому ждите ошибку в несколько сотен метров в середине большой карты. У одного семейства карт в hini стоят углы другой карты (они охватывают долю её настоящего размера); это обнаруживается, и это семейство размещается подгонкой по ориентирам: города и аэродромы из собственных баз данных положений игры (`*.ldfbin`) сравниваются с их настоящими положениями, среднеквадратичная ошибка — пара километров (города — с аэродромами, названными в их честь, и координаты настоящих мест с точностью около километра); JSON перечисляет каждый ориентир и его отклонение |
| Маска воды (`water.wtr`: четыре уровня пирамиды тайлов, каждый тайл — таблица блоков по 400 м, каждый блок — суша, полностью вода или частично вода с его формой в потоке битов) | контейнер читается на каждой карте (без лишнего байта в полностью декодированных файлах); форма внутри блока, частично покрытого водой, **не декодируется**. Полностью водные блоки — это вода; в частично водных блоках отсчёт — вода там, где карта воды (`height_w.dat`, тот же кодек, что у карты высот) выше земли, или, у озера, там, где земля не выше озера; сухие блоки — суша. Так убирается болото, которое карта воды одна считает водой. Реки уже, чем ячейка выходной сетки, распадаются на куски |
| Контуры городов (сетки декалей, которые перечисляет `textures.tini`: `towns.mesh`, `cities.mesh`, `city_*.mesh`, `roads_fields.mesh` и др.: плоские текстурированные треугольники тайлами по 25,6 км) | читаются на каждой карте; сохраняются грани, текстура которых — город, деревня или промышленная земля. Проверено по настоящим городам на нескольких картах (город на обоих берегах реки, слияние рек). Это контуры: здания игра ставит во время работы, а в файлах зданий нет |
| Аэродромы, мосты, здания | **не читаются**: аэродромы — это объекты миссий, здания берутся из собственного размещения игры |
| Леса (`forest_map.wtr`) | его блоки читаются так же, но почти каждый блок — «частично лес», поэтому без потока битов полезной маски леса нет; не рисуется |
| Текстуры местности | не читаются |

## Кодек карты высот {#the-heightmap-codec}

Выведен только по файлам данных; код игры не читался и не дизассемблировался.
Порядок байтов — little-endian:

```text
u32 width, u32 height, u32 sectorsX, u32 sectorsY, u32 sectorSize, f32 cellSize
u32 offset[sectorsX * sectorsY]            от начала файла, по строкам, верхняя строка первой
сектор: u16 count (байты, которые идут дальше), u16 mode ((log2 sectorSize) << 4 | LW, LW = 4),
        затем поток битов, читаемый от старшего бита к младшему:
  PRE   2 * (log2(sectorSize) - 5) битов, пока всегда 0
  LIT   первый отсчёт: знак (1), n (LW битов), величина (n + 1 бит)
  затем, пока сектор не заполнен:
    0 LIT       next = previous + LIT
    1 RUN LIT   предыдущий отсчёт повторяется RUN раз (k: 3 бита, m: k + 1 бит, RUN = m + 1),
                затем (если сектор не заполнен) next = previous + LIT
  значения 16-битные: читаются по модулю 65536
```

Неполные секторы у правого и нижнего краёв дополняются и обрезаются. Тот же кодек используется для
карты воды и для карты высот дальнего уровня детализации.

## Подгонка по ориентирам {#landmark-fits}

Там, где углы карты нельзя использовать, `landmarks.py` подгоняет аффинное преобразование из метров
игры в Землю методом наименьших квадратов: позиции в игре берутся из собственных файлов пользователя
(блоки `Airfield` в миссиях, базы данных положений карьеры), настоящие позиции — из таблиц опубликованных
координат мест в коде. В `georeference` JSON записаны матрица, начало, каждый ориентир с его
отклонением и среднеквадратичная ошибка.
